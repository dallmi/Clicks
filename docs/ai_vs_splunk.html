Wie sich beide Systeme bei einer User-Aktion verhalten, wo sie sich überschneiden und wo nicht.

2 · Mengen-Überschneidung

Lesehilfe

Linker Kreis · AppInsights: jeder Browser-Klick auf der Intranet-Oberfläche, gemessen am DOM-Click-Event. Misst User-Intent.
Überschneidung: User klickt im Intranet auf eine SharePoint-Datei und das Backend liefert sie tatsächlich aus. Hier ist 1:1-Vergleich nach Dedupe sinnvoll.
Rechter Kreis · Splunk: jeder SharePoint-Backend-Zugriff, unabhängig vom Einstiegspunkt. Misst Backend-Realität.

3 · Dedupe-Logik im Vergleich

Ein einziger User-Klick erzeugt in Splunk häufig mehrere Audit-Events (z.B. FileAccessed beim Folgen des Links plus FileDownloaded beim Stream). Damit der Vergleich mit AppInsights fair bleibt, kollabieren wir diese auf eine logische User-Aktion:

SELECT DISTINCT user_id, object_id, date_trunc('minute', ts)
FROM splunk_raw
WHERE object_id LIKE '%<filter>%'

Gleicher User · gleiche Datei · gleiche Minute = 1 Event — vergleichbar mit einem click_event in AppInsights.

5 · Praktische Konsequenz für deinen Vergleich

Die "richtige" Splunk-Operations-Auswahl hängt davon ab, welche Frage du beantworten willst:

FrageSplunk-FilterVergleichsbasis
Wie viele User greifen auf eine Datei zu? FileAccessed + FileDownloaded + FilePreviewed, deduped ≈ AI total_clicks auf File-Links
Wie viele Files werden tatsächlich heruntergeladen? FileDownloaded ohne Dedupe Niemals direkt mit AI-Downloads vergleichbar (Office/PDF-Inline-Lücke)
Wie groß ist der nicht-via-Intranet Traffic? FileAccessed deduped Splunk-Total − AI-Total = Direkt-Zugriffe
